# คู่มือเริ่มทดสอบระบบจริง (ทีม Tester)

เอกสารนี้พาไปตั้งแต่เครื่องเปล่าจนถึงการเข้าใช้งานจริงครบทุกบทบาท — ผู้ดูแล ครู นักเรียน ผู้ปกครอง — บนข้อมูลจริงของ Supabase ไม่ใช่โหมด Preview

รูปแบบการเข้าใช้งานตามมติ Product Owner:

| บทบาท | เข้าสู่ระบบด้วย |
| --- | --- |
| ครู | ชื่อ + รหัสผ่าน |
| ผู้ปกครอง | ชื่อ + รหัสผ่าน |
| นักเรียน | ชื่อ + เลขประจำตัวนักเรียน |
| ผู้ดูแล (เจ้าของระบบ) | ชื่อ + รหัสผ่าน (สมัครที่ทางเข้าส่วนตัว) |

ไม่มีการใช้อีเมล ไม่มี OTP รายวัน ไม่มีรหัสคำเชิญในเส้นทางปกติ

---

## 1. เตรียมเครื่อง (ครั้งเดียว)

ต้องมี Node.js 22 ขึ้นไป

```powershell
npm install
```

## 2. ตั้งค่าเซิร์ฟเวอร์ (ครั้งเดียวต่อ 1 Supabase project)

```powershell
./scripts/setup-supabase.ps1 -ProjectRef <project-ref>
```

สคริปต์จะทำให้ครบทุกอย่าง: link project, push migrations, deploy Edge Function ทั้งหมด (รวม `member-access` ที่เป็นประตูของ ชื่อ + รหัสผ่าน) และตั้ง secret ฝั่งเซิร์ฟเวอร์

ระหว่างทางจะถาม 2 อย่าง

1. **รหัสเจ้าของ (owner access code)** — ยาวอย่างน้อย 12 ตัวอักษร เก็บไว้ให้ดี ใช้สร้างโรงเรียนแรกเท่านั้น ระบบเก็บเฉพาะค่าแฮช
2. **Allowed origins** — ใส่ URL ที่จะเปิดเว็บ เช่น `http://localhost:5173` (ใส่หลายค่าได้ คั่นด้วยจุลภาค) ถ้าไม่ตรง เบราว์เซอร์จะถูก CORS บล็อกและทุกปุ่มจะเงียบ

## 3. ตั้งค่าเว็บ

คัดลอกค่าจาก Supabase Dashboard → Project Settings → API ลงไฟล์ `apps/web/.env.local`

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon key>
```

anon key ปลอดภัยสำหรับเบราว์เซอร์ ส่วน service role key ห้ามใส่ที่นี่เด็ดขาด

```powershell
npm run dev
```

เปิด http://localhost:5173

---

## 4. สร้างโรงเรียนและบัญชีผู้ดูแล

1. เปิด **http://localhost:5173/owner/access** โดยตรง (ไม่มีลิงก์จากหน้าไหน เป็นทางเข้าส่วนตัว)
2. กรอก ชื่อจริง / นามสกุล / รหัสผ่าน → กด **สร้างบัญชีและไปขั้นถัดไป**
   บัญชีนี้ยังไม่มีสิทธิ์ใด ๆ จนกว่าจะผ่านขั้นถัดไป
3. กรอก **รหัสยืนยันเจ้าของ** (ที่ตั้งไว้ในข้อ 2) พร้อมชื่อโรงเรียน รหัสโรงเรียน ปีการศึกษา ภาคเรียน
4. สำเร็จ → เข้าหน้าแรกในฐานะผู้ดูแลของโรงเรียนนั้นทันที

ครั้งต่อไปเข้าที่หน้า `/login` → เลือก **ครู** → ชื่อ + รหัสผ่านเดิม

> หนึ่งบัญชีสร้างโรงเรียนได้ครั้งเดียว ถ้าจะทดสอบโรงเรียนที่สอง ให้สร้างบัญชีเจ้าของใหม่

## 5. ใส่ข้อมูลตั้งต้น (ผู้ดูแลหรือครู)

ทำตามลำดับนี้เพื่อให้ทุกหน้าจอมีข้อมูลให้ทดสอบ

1. `/subjects` — มี 8 กลุ่มสาระให้อยู่แล้ว เพิ่ม/แก้ไขได้
2. `/classes` — สร้างห้องเรียน เช่น ป.4/1 พร้อมกำหนดความจุ
3. `/students` — เพิ่มนักเรียนทีละคน หรือ `/import` นำเข้าจาก CSV/Excel
   **ต้องกรอกเลขประจำตัวนักเรียนให้ถูกต้อง** เพราะเป็นสิ่งที่นักเรียนใช้เข้าระบบ
4. `/timetable` — ตารางสอน (ถ้าจะทดสอบส่วนนี้)
5. `/assignments` — สร้างงานแล้วกดเผยแพร่ เพื่อให้นักเรียนและผู้ปกครองเห็น

## 6. ทดสอบบัญชีครู

1. `/register` → เลือก **ครู**
2. กรอก ชื่อจริง / นามสกุล / โรงเรียน (พิมพ์แล้วเลือกจากรายการ) / รหัสผ่าน / ยืนยันรหัสผ่าน
3. กด **สร้างบัญชีและเข้าใช้งาน** → เข้าหน้าครูทันที ไม่ต้องรออนุมัติ
4. ออกจากระบบ แล้วเข้าใหม่ที่ `/login` → **ครู** → ชื่อ + รหัสผ่าน

## 7. ทดสอบบัญชีนักเรียน

1. ครูสร้างระเบียนนักเรียนไว้แล้วในข้อ 5
2. นักเรียนเปิด `/student` → กรอก ชื่อ + เลขประจำตัวนักเรียน → **เข้าใช้งาน**
3. ถ้ายังไม่มีระเบียน ใช้ `/student/first-time` (ชื่อจริง นามสกุล เลขประจำตัว โรงเรียน) ระบบจะเชื่อมกับระเบียนเดิมถ้ามี ไม่สร้างซ้ำ

## 8. ทดสอบบัญชีผู้ปกครอง และการเพิ่มลูก

1. `/register` → เลือก **ผู้ปกครอง** → ชื่อจริง / นามสกุล / รหัสผ่าน / ยืนยันรหัสผ่าน
   ไม่ต้องเลือกโรงเรียน ไม่ต้องรู้ข้อมูลลูก
2. เข้าระบบแล้วจะเจอหน้า **ลูกของฉัน** → กด **+ เพิ่มลูก**
3. กรอก **ชื่อจริงของลูกอย่างเดียว** → กด **ค้นหา**
4. เลือกการ์ดของลูก (การ์ดแสดงแค่ชื่อ โรงเรียน ห้อง และเลขประจำตัวแบบปิดบัง เพื่อแยกเด็กชื่อซ้ำ) → กด **เชื่อมบัญชี**
5. ผลลัพธ์มี 2 แบบ
   - **เชื่อมแล้ว** ทันที เมื่อโรงเรียนบันทึกผู้ปกครองชื่อนี้ของเด็กคนนี้ไว้ก่อนแล้ว
   - **รอครูอนุมัติ** ในกรณีอื่น
6. ฝั่งครู/ผู้ดูแล เปิด `/parents` → หัวข้อ **คำขอเชื่อมบัญชีผู้ปกครอง** → กด **อนุมัติ**
7. ผู้ปกครองรีเฟรช → เห็นข้อมูลลูกครบ: ห้อง ครู งาน คะแนน เกรด การเข้าเรียน ปฏิทิน การแจ้งเตือน
8. เพิ่มลูกคนที่สองได้ด้วยวิธีเดียวกัน และกด **ยกเลิกการเชื่อม** ได้เอง

## 9. ทดสอบการลืมรหัสผ่าน (ไม่ใช้อีเมล)

1. ผู้ใช้เปิด `/forgot-password` → เลือกบทบาท → กรอกชื่อ → ส่งคำขอ
   หน้าจอตอบเหมือนกันเสมอ ไม่บอกว่ามีบัญชีนี้หรือไม่
2. ครู/ผู้ดูแลเปิด `/parents` → หัวข้อ **คำขอตั้งรหัสผ่านใหม่** → กด **ตั้งรหัสผ่านใหม่**
3. ระบบสร้างรหัสผ่านใหม่แสดงบนหน้าจอครั้งเดียว ให้แจ้งเจ้าของบัญชีโดยตรง
   ระบบไม่แสดงรหัสผ่านเดิมทุกกรณี

## รายการที่ควรทดสอบ

| หัวข้อ | สิ่งที่ต้องเห็น |
| --- | --- |
| ครูชื่อซ้ำกัน 2 คน | เข้าได้ถูกบัญชีของตัวเอง ถ้ารหัสผ่านซ้ำกันด้วย ระบบจะให้เลือกโรงเรียนก่อน |
| ผู้ปกครองชื่อซ้ำกัน | เหมือนครู |
| เด็กชื่อซ้ำกัน | ค้นหาแล้วขึ้นหลายการ์ด ระบบไม่เลือกให้เอง |
| รหัสผ่านผิด | ขึ้นข้อความเดียว "ชื่อหรือรหัสผ่านไม่ถูกต้อง" ไม่บอกว่าผิดช่องไหน |
| ลองผิดซ้ำ ๆ | ผิดครบ 5 ครั้งใน 15 นาที ระบบล็อกชั่วคราวและบอกเวลาที่ต้องรอ |
| ผู้ปกครองที่ยังไม่อนุมัติ | เห็นสถานะ "รอครูอนุมัติ" แต่ยังไม่เห็นข้อมูลการเรียนของเด็ก |
| ผู้ปกครองข้ามคน | ไม่เห็นข้อมูลเด็กที่ไม่ได้เชื่อม |
| นักเรียนข้ามคน | ไม่เห็นข้อมูลเพื่อน |
| ต่างโรงเรียน | ไม่เห็นข้อมูลข้ามโรงเรียน |
| ปิดเบราว์เซอร์แล้วเปิดใหม่ | ยังอยู่ในระบบ ความสัมพันธ์กับลูกยังอยู่ |
| ออฟไลน์ | ใช้งานต่อได้ และซิงก์กลับเมื่อเน็ตกลับมา (ต้องเคยเข้าออนไลน์มาก่อน) |

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและทางแก้ |
| --- | --- |
| กดปุ่มแล้วไม่มีอะไรเกิดขึ้น | `ALLOWED_ORIGINS` ไม่ตรงกับ URL ที่เปิดอยู่ — ตั้งใหม่ด้วย `npx supabase secrets set ALLOWED_ORIGINS=http://localhost:5173` |
| ขึ้น "ชื่อหรือรหัสผ่านไม่ถูกต้อง" ทั้งที่มั่นใจว่าถูก | ชื่อต้องตรงกับตอนสมัคร (ตัวพิมพ์และช่องว่างไม่สำคัญ แต่ตัวสะกดสำคัญ) |
| หน้า "บัญชีนี้ยังไม่มีสิทธิ์ในโรงเรียน" | บัญชีครูที่ยังไม่ได้ผูกโรงเรียน ให้สมัครใหม่ผ่าน `/register` แล้วเลือกโรงเรียน |
| ทางเข้าเจ้าของขึ้น `SERVER_CONFIGURATION_ERROR` | ยังไม่ได้ตั้ง `ADMIN_ACCESS_CODE_HASH` — รัน `./scripts/setup-supabase.ps1` อีกครั้ง |
| ทางเข้าเจ้าของขึ้น "ยืนยันสิทธิ์ไม่สำเร็จ" ซ้ำ ๆ | ผิดครบ 5 ครั้ง ระบบล็อก 30 นาที |
| นักเรียนเข้าไม่ได้ | ตรวจว่าเลขประจำตัวในระเบียนตรงกับที่กรอก และสถานะการเข้าใช้งานของนักเรียนยังเปิดอยู่ |

## หมายเหตุด้านความปลอดภัย

- รหัสผ่านทั้งหมดอยู่กับ Supabase Auth ระบบไม่เก็บ ไม่เทียบ และไม่เห็นรหัสผ่านเอง
- ชื่อไม่ใช่สิ่งยืนยันตัวตน การเข้าถึงข้อมูลนักเรียนมาจากความสัมพันธ์ที่โรงเรียนรับรองเท่านั้น
- ทุกการสมัคร เข้าระบบ เชื่อมลูก อนุมัติ และตั้งรหัสผ่านใหม่ ถูกบันทึกไว้ตรวจสอบย้อนหลังได้
- RLS ยังบังคับเหมือนเดิมทุกตาราง การเข้าระบบแบบชื่อ + รหัสผ่านได้ session ปกติของ Supabase ไม่มีการลดทอนสิทธิ์
