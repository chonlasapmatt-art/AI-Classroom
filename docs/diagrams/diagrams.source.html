1สถาปัตยกรรมภาพรวม

สามชั้นที่แยกหน้าที่กันชัดเจน หน้าจอเขียนลงเครื่องก่อนเสมอ งานที่ต้องเชื่อถือผ่าน Edge Function และการตัดสินใจเรื่องสิทธิ์ทุกครั้งเกิดขึ้นในฐานข้อมูล

ทำไมต้องมีสองเส้นทาง — การอ่านธรรมดาผ่าน RLS ได้เลยเพราะ policy กรองแถวให้แล้ว ส่วนงานที่ต้องถือความลับ (ออกรหัส เข้าระบบ ระบายคิวแจ้งเตือน) ต้องผ่าน Edge Function เพราะ secret อยู่ที่นั่นและต้องไม่มีวันไปอยู่ในเบราว์เซอร์

2เส้นทางของการเขียนหนึ่งครั้ง

ระบบเป็น local-first ทุกการเขียนลงเครื่องก่อนเสมอแล้วค่อยเข้าคิว ครูที่เช็กชื่อตอนไม่มีสัญญาณกำลังทำงานถูกต้อง ไม่ใช่กำลังเจอข้อผิดพลาด

idempotency key — คิวส่งซ้ำได้โดยไม่เกิดรายการซ้ำ เครื่องที่ส่งไปแล้วแต่ไม่ได้รับคำตอบ (สัญญาณหลุดกลางทาง) ส่งใหม่ได้อย่างปลอดภัย

3ชั้นของสิทธิ์

คำขอหนึ่งครั้งผ่านด่านอะไรบ้าง และด่านไหนคือด่านที่มีผลจริง

สิทธิ์ของครู ขึ้นกับความรับผิดชอบ ไม่ใช่ตำแหน่ง

ความรับผิดชอบเขียนงาน/คะแนนของวิชานั้นดูข้อมูลทั้งห้อง
ครูเจ้าของวิชา (subject owner)ได้ได้
ครูร่วมสอน (co-teacher)ไม่ได้ได้
ครูประจำชั้น (advisor)ไม่ได้ได้
ครูผู้ช่วยประจำชั้น (assistant)ไม่ได้ได้

4สายการแจ้งเตือนผู้ปกครอง

เหตุการณ์ในโรงเรียนเข้าคิวโดยอัตโนมัติผ่าน trigger ตัวส่งระบายคิวออก LINE และทุกครั้งที่ตัวส่งทำงานจะบันทึกไว้ — เพื่อให้ “ตัวส่งตาย” เป็นสิ่งที่มองเห็น ไม่ใช่ความเงียบ

จุดที่เคยพลาดมาแล้ว — โค้ดตัวส่งเขียนเสร็จและถูกต้อง แต่ไม่มีอะไรเรียกมัน ข้อความจึงค้างในคิวโดยที่ทุกหน้าจอดูปกติ และโรงเรียนเข้าใจว่าแจ้งผู้ปกครองไปแล้ว ตอนนี้ปิดช่องนี้ด้วยสองอย่าง: ฟังก์ชันตั้งเวลาให้ pg_cron และการบันทึกทุกครั้งที่ตัวส่งทำงาน

5ความสัมพันธ์ของข้อมูลหลัก

66 ตารางจัดกลุ่มได้เป็นห้าวง — โครงสร้างโรงเรียน คน การเรียนการสอน การประเมิน และระบบ

6บทบาทและสิ่งที่ต้องทำตอน deploy

ใครเข้าระบบด้วยอะไร

ไม่มีทางเข้าไหนถามอีเมล · อีเมลใช้เพื่อกู้รหัสผ่านเท่านั้น

บทบาทใช้อะไรเข้าระบบหน้าจอเห็นอะไร
ครูชื่อ + รหัสครู/loginห้องและวิชาที่รับผิดชอบ
ผู้ปกครองชื่อ + รหัสผ่าน/loginเฉพาะลูกที่ยืนยันและยินยอมแล้ว
นักเรียนชื่อ + เลขประจำตัว/loginงาน คะแนน และประกาศของตัวเอง
ผู้ดูแลโรงเรียนชื่อ + รหัสผ่าน/admin-accessทุกอย่างในโรงเรียนของตัวเอง
ผู้ดูแลแพลตฟอร์มชื่อ + รหัสผ่าน + รหัสสิทธิ์ (+ MFA)/platformสุขภาพระบบทุกโรงเรียน · ไม่เห็นคะแนนเด็ก

#สิ่งที่ต้องทำถ้าไม่ทำจะเป็นอย่างไร
1ตั้ง PRODUCT_KEY_SECRET (≥32 ตัวอักษร)ลูกค้าเปิดใช้งานครั้งแรกไม่ได้ ระบบปฏิเสธออกคีย์
2ตั้ง NOTIFICATION_DISPATCH_SECRETตัวส่งแจ้งเตือนปฏิเสธทุกคำขอ
3ตั้งเวลาเรียก notification-dispatchข้อความค้างในคิว โรงเรียนเข้าใจว่าแจ้งไปแล้ว
4supabase db push + deploy Edge Functionsmigration ใหม่ยังไม่มีผล
5ตั้ง ALLOWED_ORIGINS ให้ตรงโดเมนจริงทุกคำขอถูก CORS ปฏิเสธ
6ทดสอบกู้คืนข้อมูลจริงมีไฟล์สำรองที่ไม่มีใครรู้ว่ากู้ได้จริงหรือไม่
สถานะ: CONDITIONALLY READY — ข้อ 3 และข้อ 6 เป็นขั้นตอน deploy ไม่ใช่โค้ดที่ขาด แต่ทั้งสองข้อต้องทำจริงบน project จริงก่อนเปิดใช้กับครอบครัวจริง เอกสารนี้ไม่ประกาศว่าระบบ production ready เพราะยังไม่ได้ทดสอบครบบนเครื่องจริงทุกขนาดจอ
