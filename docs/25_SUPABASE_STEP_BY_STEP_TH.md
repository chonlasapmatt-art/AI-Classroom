# ต่อ Supabase ทีละขั้น (สำหรับเปิดทดสอบกับผู้ใช้จริง)

คู่มือนี้เขียนสำหรับคนที่เพิ่งสร้าง Supabase project และยังไม่เคยใช้ Supabase CLI มาก่อน ทำตามลำดับจนจบแล้วระบบจะพร้อมให้ครู นักเรียน และผู้ปกครองสมัครและใช้งานจริง

เอกสารอ้างอิงเชิงเทคนิคอยู่ที่ [`20_INSTALLATION_AND_SUPABASE.md`](20_INSTALLATION_AND_SUPABASE.md) และ [`21_DEPLOYMENT_RUNBOOK.md`](21_DEPLOYMENT_RUNBOOK.md)

## สิ่งที่ต้องมี

- Node.js 22 ขึ้นไป
- Supabase project ที่สร้างไว้แล้ว 1 อัน (แนะนำแยกอันสำหรับทดสอบกับของจริง)
- รหัสผ่านฐานข้อมูล (Database password) ที่ตั้งไว้ตอนสร้าง project — หาไม่เจอให้ตั้งใหม่ได้ที่ Dashboard → Project Settings → Database → Reset database password

## ขั้นที่ 1 — เก็บค่าจาก Dashboard

เปิด https://supabase.com/dashboard เลือก project แล้วจดค่า 3 อย่าง

| ค่า | หาได้จาก | เอาไปใช้ที่ไหน |
|---|---|---|
| Project ref | URL ของ dashboard: `.../project/<project-ref>` | สคริปต์ตั้งค่า |
| Project URL | Project Settings → API → Project URL | `.env.local` |
| anon public key | Project Settings → API → Project API keys → `anon` `public` | `.env.local` |

**สำคัญ:** คีย์ `service_role` ห้ามนำมาใส่ในแอปฝั่งเบราว์เซอร์เด็ดขาด แอปนี้ใช้เฉพาะ `anon` key ซึ่งปลอดภัยต่อการเปิดเผยในเบราว์เซอร์ เพราะสิทธิ์จริงถูกบังคับด้วย RLS ที่ฐานข้อมูล

## ขั้นที่ 2 — ติดตั้งฐานข้อมูลและ Edge Function

รันคำสั่งเดียวจากโฟลเดอร์โปรเจกต์ (PowerShell)

```powershell
./scripts/setup-supabase.ps1 -ProjectRef <project-ref>
```

สคริปต์จะทำให้ตามลำดับ

1. `supabase link` — จะถามรหัสผ่านฐานข้อมูล พิมพ์แล้วจะไม่แสดงบนหน้าจอ
2. `supabase db push` — สร้างตาราง RLS และฟังก์ชันทั้งหมดตามลำดับ migration
3. deploy Edge Function ทั้ง 6 ตัว (`line-notify` deploy แบบ `--no-verify-jwt` เพราะเป็น webhook ที่ตรวจลายเซ็นของ LINE เอง)
4. ตั้งค่า secret ฝั่งเซิร์ฟเวอร์ โดยสุ่ม HMAC secret ให้อัตโนมัติ และถาม **รหัสเจ้าของระบบ (owner access code)** ที่คุณจะใช้สร้างโรงเรียนแรก

รหัสเจ้าของระบบจะถูกแปลงเป็น SHA-256 ก่อนส่งขึ้นเซิร์ฟเวอร์ ตัวรหัสจริงไม่ถูกเก็บไว้ที่ใดเลย ทั้งในเครื่อง ในเซิร์ฟเวอร์ และใน repository — **จดเก็บเองให้ดี ถ้าลืมต้องตั้งใหม่แล้ว deploy secret ใหม่**

ถ้าอยากอัปเดตเฉพาะโค้ดโดยไม่แตะ secret เดิม

```powershell
./scripts/setup-supabase.ps1 -ProjectRef <project-ref> -SkipSecrets
```

## ขั้นที่ 3 — ตั้งค่าแอปฝั่งเบราว์เซอร์

สร้างไฟล์ `apps/web/.env.local` (ไฟล์นี้ถูก gitignore ไว้แล้ว ไม่ขึ้น repository)

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon public key>
VITE_APP_ENV=staging
VITE_SYNC_PROTOCOL_VERSION=1
```

แล้วรัน

```bash
npm run dev
```

หน้าแรกจะเปลี่ยนจาก “ตั้งค่า Supabase” เป็นหน้าเข้าสู่ระบบจริง

## ขั้นที่ 4 — สร้างโรงเรียนแรก

1. เปิด URL `/owner/access` โดยพิมพ์เองในช่อง address (หน้านี้ตั้งใจไม่ลิงก์จากเมนูใด ๆ)
2. สร้างบัญชีเจ้าของด้วย ชื่อจริง นามสกุล และรหัสผ่าน — บัญชีนี้ยังไม่มีสิทธิ์ใด ๆ ในขั้นนี้
3. กรอกรหัสเจ้าของระบบจากขั้นที่ 2 พร้อมชื่อโรงเรียน รหัสโรงเรียน (A-Z 0-9 ขีดกลาง) ปีการศึกษา และภาคเรียน
4. ครั้งต่อไปเข้าที่ `/login` เลือก **ครู** แล้วใช้ชื่อกับรหัสผ่านเดิม

การซ่อน URL ไม่ใช่การป้องกัน — ต่อให้มีคนเดา URL เจอ ก็ยังต้องผ่านการตรวจรหัสฝั่งเซิร์ฟเวอร์ ซึ่งมีการจำกัดจำนวนครั้ง ล็อกชั่วคราวเมื่อผิดซ้ำ และบันทึก audit ทุกครั้ง

## ขั้นที่ 5 — เตรียมข้อมูลก่อนเชิญผู้ใช้จริง

ทำตามลำดับนี้ที่หน้าเว็บ

1. **ปีการศึกษา** (`/promotion`) — เปิดปีการศึกษาและตั้งเป็นปีที่ใช้งาน
2. **รายวิชา** (`/subjects`) — มี 8 กลุ่มสาระมาตรฐานให้แล้ว เพิ่มหรือแก้ได้
3. **ห้องเรียน** (`/classes`) — สร้างห้องพร้อมกำหนดความจุ
4. **ครู** (`/teachers`) — เพิ่มครู ติ๊ก “สร้างคำเชิญบัญชีเข้าใช้งาน” เพื่อรับรหัส 8 หลัก
5. **นักเรียน** (`/students`) — เพิ่มรายชื่อทีละคนหรือนำเข้า CSV แล้วกด “เปิดบัญชีเข้าใช้งาน” เมื่อต้องการให้นักเรียนล็อกอิน
6. **ผู้ปกครอง** (`/parents`) — เพิ่มผู้ปกครองพร้อมอีเมล จะได้รหัสคำเชิญเช่นกัน
7. **ตารางสอน** (`/timetable`) — จัดคาบเรียนรายสัปดาห์

## ขั้นที่ 6 — ผู้ใช้จริงเข้าใช้งาน

ก่อนทดสอบ Forgot Password ต้องตั้ง Custom SMTP แล้วรัน `./scripts/setup-supabase.ps1 -ProjectRef <project-ref> -PushAuthConfig`; Hosted Free tier ที่ใช้ default email provider ไม่อนุญาต custom recovery template

การเข้าสู่ระบบปกติไม่ใช้อีเมลและไม่ใช้รหัสคำเชิญ อีเมลที่กรอกตอนสมัครใช้กู้รหัสผ่านเท่านั้น

- **ครู** — `/register` → เลือก **ครู** → ชื่อจริง นามสกุล โรงเรียน อีเมลกู้คืน รหัสผ่าน → ใช้งานได้ทันที ผู้ดูแลเพิกถอนภายหลังได้ที่ `/teachers`
- **นักเรียน** — `/student` → ชื่อ + เลขประจำตัวนักเรียน (ครูสร้างระเบียนไว้ก่อนแล้ว) หรือ `/student/first-time` เมื่อยังไม่มีระเบียน
- **ผู้ปกครอง** — `/register` → เลือก **ผู้ปกครอง** → ชื่อจริง นามสกุล อีเมลกู้คืน รหัสผ่าน → เข้าหน้า **ลูกของฉัน** → กรอกชื่อจริงของลูกเพื่อค้นหาและเชื่อมบัญชี
  ถ้าโรงเรียนบันทึกผู้ปกครองชื่อนี้ของเด็กคนนี้ไว้แล้ว ระบบเชื่อมทันที ถ้าไม่ใช่จะเป็นคำขอให้ครูอนุมัติที่ `/parents`

รหัสคำเชิญ 8 หลักยังใช้ได้อยู่สำหรับกรณีที่โรงเรียนต้องการผูกบัญชีกับระเบียนเดิมโดยตรง มีอายุ 48 ชั่วโมง ใช้ได้ครั้งเดียว และผูกกับอีเมลที่ระบุไว้

## ขั้นที่ 7 — ตรวจก่อนเปิดให้ผู้ใช้จริง

| ตรวจอะไร | ดูที่ไหน | ต้องเห็นอะไร |
|---|---|---|
| ซิงก์ทำงาน | ป้ายมุมบนขวา | “ซิงก์เรียบร้อย” และกดเพื่อซิงก์ทันทีได้ |
| ข้ามเครื่องได้ | เปิดอีกเบราว์เซอร์แล้วล็อกอินอีกบัญชี | เห็นห้องเรียน รายวิชา และนักเรียนชุดเดียวกัน |
| ออฟไลน์ได้ | ปิดเน็ตแล้วเช็กชื่อ | บันทึกได้ ป้ายขึ้น “ทำงานออฟไลน์” แล้วซิงก์เองเมื่อเน็ตกลับมา |
| สำรองข้อมูล | `/operations` | สร้างไฟล์สำรองได้ และกู้คืนจากไฟล์นั้นได้ |

## ข้อมูลตัวอย่างสำหรับรอบทดสอบ

หน้า `/operations` มีปุ่มสร้างข้อมูลตัวอย่าง (เฉพาะผู้ดูแล) ซึ่งเขียนผ่านเส้นทางจริงทุกขั้น และลบได้เฉพาะสิ่งที่มันสร้างเท่านั้น ห้ามใช้กับโรงเรียนที่มีข้อมูลผู้ใช้จริงแล้ว

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| หน้าแรกยังเป็น “ตั้งค่า Supabase” | ไม่มี `apps/web/.env.local` หรือรันไม่ได้รีสตาร์ท | สร้างไฟล์แล้วรัน `npm run dev` ใหม่ |
| `SERVER_CONFIGURATION_ERROR` ตอนกรอกรหัสเจ้าของ | ยังไม่ได้ตั้ง `ADMIN_ACCESS_CODE_HASH` | รันสคริปต์ขั้นที่ 2 ใหม่โดยไม่ใส่ `-SkipSecrets` |
| `INVITATION_EMAIL_MISMATCH` | สมัครด้วยอีเมลคนละตัวกับที่สร้างคำเชิญ | สร้างคำเชิญใหม่ให้ตรงกับอีเมลที่ใช้สมัคร |
| เข้าสู่ระบบแล้วค้างที่หน้ารอเชื่อมบัญชี | ยังไม่ได้กรอกรหัสคำเชิญ หรือครูยังไม่ถูกยืนยัน | กรอกรหัส หรือให้ผู้ดูแลกดยืนยันสถานะครู |
| อุปกรณ์ที่สองไม่เห็นห้องเรียน | ยังไม่ได้ซิงก์รอบแรก | กดป้ายสถานะซิงก์ที่มุมบนขวาหนึ่งครั้ง |

## สิ่งที่ยังต้องมีของจริงจากภายนอก

- **LINE OA** — ต้องมี channel จริงจึงจะตั้ง `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET` ได้ ระบบส่วนอื่นทำงานได้โดยไม่ต้องมี
- **โดเมนสำหรับ production** — ต้องใส่ใน `ALLOWED_ORIGINS` และตั้งเป็น Site URL ใน Supabase Auth
